# 安全说明与上线检查清单

## 1. 已实现的机制

| 层面 | 措施 |
| --- | --- |
| 口令 | BCrypt 哈希存储（种子账号哈希为现场生成并回验） |
| 会话 | Sa-Token（UUID token，24h 超时，持久化于 `sys_token` 表）；同名 Cookie 开启 `HttpOnly`，避免 XSS 读取 |
| 鉴权 | 接口级角色注解（`@SaCheckRole` 等）+ 路由层 `meta.roles` 双收口；`JwtAuthenticationFilter` 维护白名单 |
| 租户隔离 | `MerchantContext` + Service 层归属断言（不依赖外键），关键越权路径有测试覆盖 |
| 输入校验 | DTO 注解校验（手机号、金额区间、分页上限等）+ 统一异常出口 |
| 审计 | `operation_log` 记录关键操作（AOP 切面写入） |
| 限流 | `@RateLimit` 注解式限流，Redis 不可用时降级放行 |
| 上传 | 大小上限 10MB/文件、20MB/请求；目录与访问前缀分离，避免把源码树当数据目录 |
| 生产加固 | prod profile 必需变量缺失即启动失败；关闭 Swagger / Knife4j；CORS 白名单显式配置 |

## 2. 上线前检查清单

- [ ] 修改数据库口令，删除或禁用所有演示账号（`admin` / `merchant` / `user` / `kefu`）
- [ ] 为真实用户重新生成口令哈希，不复用 `init.sql` 中的值
- [ ] 配置 `CORS_ALLOWED_ORIGINS` 为真实域名，不要留 `*` 或 localhost
- [ ] 启用 HTTPS，并在网关层加 HSTS；后端不直接暴露公网端口
- [ ] `UPLOAD_PATH` 指向独立数据目录，限制可执行文件类型，配置定期备份
- [ ] 关闭 `springdoc` / `knife4j`（prod profile 已默认关闭，确认未被覆盖）
- [ ] 配置 Redis 口令与网络隔离；或在明确接受降级行为的前提下不启用限流
- [ ] 日志接入集中采集，敏感字段（口令、token）不得落盘
- [ ] 数据库账号遵循最小权限原则，不使用 root
- [ ] 制定备份与回滚流程（数据库与上传目录需成对恢复）

## 3. 已知限制

- 仓库与演示数据**不含真实个人信息**；示例账号、示例商品与示例图片均为公开占位内容。
- 支付为演示实现（无真实支付网关回调校验），接入真实支付前必须补齐签名校验与幂等回调。
- 推荐 / 预测算法未做离线评估，不构成业务决策依据。
- 未见安全扫描（SAST / 依赖漏洞扫描）接入，建议在 CI 中增加 `mvn dependency-check` 或 Dependabot。

## 4. 漏洞报告

如发现安全问题，请通过仓库 Issue 私密反馈或在 Issue 中描述复现步骤（请勿附带真实用户数据）。维护者会尽快确认与修复。
